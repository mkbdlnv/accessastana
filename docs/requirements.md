# Требования к системе AccessAstana

Версия 1.1 от 16.11.2026. Изменения требований перечислены в разделе 6.
Диаграмма вариантов использования: `docs/diagrams/png/usecases.png`.

## 1. Заинтересованные стороны и роли пользователей

| Роль | Цель | Как пользуется системой |
|---|---|---|
| Урбанист / сотрудник акимата | Найти районы с плохой пешеходной доступностью и обосновать размещение объектов | Веб-карта, сценарии, оптимизация, PDF-отчёт |
| Житель / исследователь | Узнать доступность своего района летом и зимой | Веб-карта (только просмотр) |
| Аналитик данных | Загрузить и обновить данные, пересчитать результаты, подготовить отчёт для статьи | CLI `accessastana` |
| DevOps-инженер | Развернуть и сопровождать сервер | Docker Compose, скрипты резервного копирования, GitHub Actions |

## 3. Нефункциональные требования (NFR)

| ID | Категория (ISO/IEC 25010) | Требование | Измеренное значение | Источник измерения |
|---|---|---|---|---|
| NFR-01 | Производительность | p95 ответа `POST /scenarios` на данных Астаны < 2 с | **0,006 с** | `docs/final/evidence/benchmark.txt` |
| NFR-02 | Производительность | p95 `POST /optimize` (k = 5) < 5 с | MCLP **0,037 с**, p-медиана **0,806 с** | там же |
| NFR-03 | Производительность | Полный офлайн-пайплайн для Астаны ≤ 15 мин на ноутбуке | **363 с** | `docs/final/evidence/fresh_start.txt` |
| NFR-04 | Сопровождаемость | Покрытие тестами `analysis` + `api` ≥ 70%, без ошибок ruff, mypy, ESLint | **97%**, ошибок нет | `backend_checks.txt`, CI `ci.yml` |
| NFR-05 | Воспроизводимость | Каждое число в отчёте воспроизводится одной командой из версионированных входов | `accessastana pipeline`, таблица `import_runs` с SHA-256 | `fresh_start.txt` |
| NFR-06 | Переносимость | Запуск в Docker на linux/amd64 и arm64 | Образы собираются; PostGIS только amd64 (на arm — через эмуляцию) | `docker_ci_checks.txt` |
| NFR-07 | Безопасность | Секреты только в переменных окружения; порт БД в продакшене не публикуется; CORS ограничен | `.env.example`, `docker-compose.prod.yml` | обзор конфигурации |
| NFR-08 | Надёжность | `/health` проверяет БД (503 при недоступности); контейнеры с `restart: unless-stopped` | реализовано | `api/routers`, `docker-compose.prod.yml` |
| NFR-09 | Защита от перегрузки | Ограничения: ≤ 50 объектов в сценарии, k ≤ 20 | реализовано | `test_scenarios` (422), `test_optimize` (422) |
| NFR-10 | Юридические требования | Соблюдение лицензий ODbL и CC BY 4.0; правила использования Nominatim не нарушаются (не используется) | атрибуции в UI, PDF, API | `test_us10_attribution` |
| NFR-11 | Удобство использования | Интерфейс работает при ширине телефона и не падает при недоступном API | проверено агентом-тестировщиком headless-браузером | отчёт о проверке фронтенда (сессия разработки) |
| NFR-12 | Ресурсы сервера | Работа на одном EC2 t3.medium (4 ГБ ОЗУ) | лимиты памяти в compose: db 1 ГБ, api 1,5 ГБ, nginx 128 МБ | `docker-compose.prod.yml` |

## 4. Пользовательские истории (user stories) с критериями приёмки

Формат: «Как <роль>, я хочу <действие>, чтобы <ценность>». Критерии приёмки
(AC) проверяются автоматическими тестами `tests/acceptance/test_user_stories.py`.

**US-01.** Как урбанист, я хочу видеть на карте время пешком до ближайшего объекта выбранной категории, чтобы находить плохо обслуживаемые места.
- AC1: на каждую H3-ячейку города приходится одно значение. AC2: единица — минуты. AC3: `null` означает «недоступно в пределах 60 мин». AC4: для каждой ячейки возвращается население.

**US-02.** Как житель, я хочу сравнить лето и зиму, чтобы понимать, как климат меняет доступность.
- AC1: зимнее время для ячейки никогда не меньше летнего. AC2: профили показывают скорость и допустимое время; зимой скорость ниже, в мороз допустимое время меньше.

**US-03.** Как урбанист, я хочу сравнить районы по доле жителей в пределах 5/10/15 мин, чтобы расставить приоритеты.
- AC1: доли лежат в [0, 1]. AC2: доля растёт с порогом (5 ≤ 10 ≤ 15). AC3: есть строка «город в целом».

**US-04.** Как исследователь, я хочу видеть составной 15-минутный индекс, чтобы оценивать «город 15 минут» одним числом.
- AC1: значение индекса в [0, 1] для каждой ячейки.

**US-05.** Как урбанист, я хочу добавить на карту новый объект и сразу увидеть эффект.
- AC1: охват не уменьшается. AC2: изменившиеся ячейки перечислены, и ячейка с новым объектом среди них. AC3: ответ приходит быстрее 2 с.

**US-06.** Как урбанист, я хочу смоделировать закрытие объекта.
- AC1: охват не увеличивается.

**US-07.** Как урбанист, я хочу получить рекомендации по размещению k новых объектов.
- AC1: не больше k мест с координатами. AC2: сообщается статус решателя. AC3: сумма приростов по местам равна общему приросту охвата.

**US-08.** Как аналитик, я хочу скачать PDF-отчёт с таблицами и картами для статьи.
- AC1: ответ `application/pdf`.

**US-09.** Как житель, я хочу пользоваться интерфейсом на казахском или русском языке.
- AC1: во всех словарях одинаковый набор ключей. AC2: числа форматируются по нормам выбранного языка.

**US-10.** Как владелец продукта, я хочу, чтобы интерфейс показывал атрибуции данных, чтобы соблюдать лицензии.
- AC1: `/cities` содержит «OpenStreetMap», «ODbL», «Kontur», «CC BY 4.0», «Open-Meteo».

**US-11.** Как пользователь API, я хочу понятные ошибки, а не сбои.
- AC1: неизвестный город или сезон → 404. AC2: недопустимые параметры → 422. AC3: ошибки 500 не возникают.

**US-12.** Как аналитик, я хочу повторно запускать импорт без дубликатов, чтобы безопасно обновлять данные.
- AC1: повторный запуск с теми же входами пропускается и не создаёт запись в журнале. AC2: принудительный запуск заменяет строки, а не дублирует их.

## 5. Варианты использования (use cases)

| ID | Название | Актор | Основной сценарий | Связанные US / FR |
|---|---|---|---|---|
| UC-01 | Просмотреть карту времени пешком | Житель, Урбанист | Выбрать город и категорию → карта H3 перекрашивается; при наведении — время и население | US-01, FR-05, FR-11 |
| UC-02 | Сравнить сезоны («extend» UC-01) | Житель, Урбанист | Переключить «Лето / Зима / Сильный мороз» | US-02, FR-03 |
| UC-03 | Сравнить районы | Урбанист | Таблица районов на вкладке «Доступность» | US-03, FR-06 |
| UC-04 | Посмотреть 15-минутный индекс | Житель | Категория «15-минутный индекс» | US-04 |
| UC-05 | Смоделировать сценарий | Урбанист | «Сценарий» → режим редактирования → клики → «Рассчитать» → таблица до/после | US-05, US-06, FR-07 |
| UC-06 | Получить рекомендации («include» UC-05) | Урбанист | «Оптимизация» → k, метод → «Оптимизировать» → номера мест на карте | US-07, FR-08 |
| UC-07 | Скачать PDF-отчёт | Урбанист, Аналитик | Кнопка «Скачать отчёт PDF» | US-08, FR-09 |
| UC-08 | Переключить язык | Житель | KK / RU / EN | US-09, FR-12 |
| UC-09 | Загрузить или обновить данные города | Аналитик | `accessastana ingest all --city astana` | US-12, FR-01…04 |
| UC-10 | Пересчитать доступность и отчёт | Аналитик | `accessastana analyze all` → `accessastana report` | FR-05, FR-09 |
| UC-11 | Развернуть сервер и восстановить БД | DevOps | `docs/deployment-aws.md`, `scripts/restore_db.sh` | NFR-06…08 |

Альтернативные потоки UC-05 и UC-06: если выбран «15-минутный индекс»,
интерфейс просит выбрать конкретную категорию. При превышении лимитов
(50 объектов, k > 20) API отвечает 422 с пояснением.

## 6. Управление изменениями требований

Процесс: запрос изменения → анализ влияния (код, данные, документы, сроки) →
решение команды → изменение в отдельной ветке и Pull Request → обновление этого
документа и журнала.

| № | Дата | Изменение | Причина | Влияние | Решение и артефакты |
|---|---|---|---|---|---|
| CR-01 | 16.11.2026 | Порог 0,5 га для садов применяется только к `leisure=garden`, а не ко всем паркам | После фильтра число парков упало со 179 до 73: отсеялись небольшие скверы | Данные POI, доступность парков | `config/categories.yaml` (`min_area_applies_to`) |
| CR-02 | 16.11.2026 | **Исключить FR-16 (полнота OSM по официальным реестрам)** | Открытого машиночитаемого реестра с координатами нет. Таблица egov.kz загружается через внутренний API (это был бы скрапинг), API data.egov.kz требует персонального ключа eGov | Убраны загрузчик, геокодирование, сопоставление, `/completeness`, вкладка UI; научная новизна сокращена до двух пунктов | миграция `0002_drop_poi_matches.py`, `docs/data-sources.md` §4 |
| CR-03 | 16.11.2026 | Коэффициенты зимней скорости взять из журнальной статьи Fossum & Ryeng (2021), а не из слайдов конференции | Проверка источников: значения отличаются (1,511 против 1,53 м/с и т. д.) | Скорости 1,244 → 1,235 и 1,104 → 1,106 м/с; результаты пересчитаны | `config/seasons.yaml`, `docs/results-astana.md` |
| CR-04 | 16.11.2026 | Добавить анализ чувствительности к порогу 10 мин | Порог — допущение без прямого источника | Новая таблица в отчёте | FR-15 |
